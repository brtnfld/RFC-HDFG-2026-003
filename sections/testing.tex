\section{Test Plan}
\label{sec:test-plan}

\subsection{Per-Dataset State Tests}
\label{sec:test-filter-state}

These tests cover \texttt{init}, \texttt{term}, and the \texttt{state}
argument (\SectionRef{sec:filter-state}).  The test filter tags its
state with \texttt{cd\_values[0]}, read back from the DCPL inside
\texttt{init}, and checks every chunk's state against the
\texttt{cd\_values} it is invoked with.  A state delivered to the wrong
dataset or the wrong pipeline entry is then detected as a mismatch, not
only as a missing pointer.

\begin{itemize}
\item \texttt{state-01} (\textbf{create lifecycle}): \texttt{H5Dcreate}
  runs \texttt{init} once, with a chunk dataspace of the dataset's rank;
  every chunk written and read receives that state; \texttt{H5Dclose} runs
  \texttt{term} once.  \texttt{init} also records the unfiltered chunk
  size (\texttt{H5Pget\_chunk} dimensions times \texttt{H5Tget\_size}),
  and the filter checks it against \texttt{nbytes} on every write.
\item \texttt{state-02} (\textbf{open lifecycle and sharing}): After
  reopening the file, two \texttt{H5Dopen} calls on one dataset run
  \texttt{init} once; a second dataset runs its own \texttt{init}; each
  dataset's reads see its own state; closing the first handle does not run
  \texttt{term}, and closing the last one does.
\item \texttt{state-03} (\textbf{duplicate filter IDs}): A pipeline with
  the same filter ID twice runs \texttt{init} twice, each call receiving
  the index of its own entry, and each entry's calls receive its own state.
\item \texttt{state-04} (\textbf{failure at create}): An \texttt{init}
  that fails makes \texttt{H5Dcreate} fail and leaves no link behind.
  When the second of two entries fails, the first entry's state is
  released (\texttt{term} count equals successful \texttt{init} count).
\item \texttt{state-05} (\textbf{failure at open}): With \texttt{init}
  failing, \texttt{H5Dopen} and \texttt{H5Dget\_create\_plist} succeed,
  \texttt{H5Dread} fails, and no \texttt{term} runs for the failed entry.
\item \texttt{state-06} (\textbf{group heaps refused}): A group whose GCPL
  carries a filter with \texttt{init} fails to create its fractal heap
  (on the first dense link insert), with an error naming the per-dataset
  requirement.
\item \texttt{state-07} (\textbf{object copy}): \texttt{H5Ocopy} of a
  chunked variable-length dataset --- the one copy path that runs the
  pipeline --- runs \texttt{init} and \texttt{term} exactly once around the
  copy, and the copied data reads back correctly.
\item \texttt{state-08} (\textbf{plugin loaded after open}): Reopen a file
  whose filter is a dynamically loaded plugin not yet registered, with no
  custom-stored blob.  Verify \texttt{H5Dopen} does not load the plugin or
  run \texttt{init}; the first \texttt{H5Dread} loads it, runs
  \texttt{init} once before the first \texttt{filter} call, and reads the
  data correctly; \texttt{term} runs once at close.  Repeat with
  \texttt{H5Zfilter\_avail} called before \texttt{H5Dopen} and verify
  \texttt{init} runs inside \texttt{H5Dopen}.
\end{itemize}

\subsection{Blob Storage Tests}
\label{sec:test-blob}

These tests exercise \texttt{H5Pappend\_filter\_blob} and the blob
on-disk format (\SectionRef{sec:blob-format}).

\begin{itemize}
\item \texttt{blob-01} (\textbf{create/open round-trip}): Create a
  chunked dataset with a filter configured via
  \texttt{H5Pappend\_filter\_blob} using the library's default
  \texttt{H5HG}-based storage (\texttt{write\_blob}/\texttt{read\_blob}
  both \texttt{NULL}). Close and reopen the file; verify the filter's
  \texttt{read\_blob} path (default reader) returns bytes identical to
  those originally passed to \texttt{H5Pappend\_filter\_blob}.
\item \texttt{blob-02} (\textbf{custom callbacks}): Repeat blob-01 with
  a test filter that implements non-NULL
  \texttt{write\_blob}/\texttt{read\_blob}/\texttt{close\_blob}; verify
  all three are invoked at the expected lifecycle points
  (\SectionRef{sec:blob-lifecycle}) and that \texttt{close\_blob} runs
  exactly once per \texttt{H5Dclose}.
\item \texttt{blob-03} (\textbf{delete reclaims heap space}): Create a
  blob-configured dataset, note the file size, delete the dataset, and
  verify (e.g., via \texttt{h5stat} or a subsequent
  \texttt{H5Fget\_freespace} check) that the heap space is reclaimed
  rather than leaked.
\item \texttt{blob-04} (\textbf{\texttt{H5Pencode}/\texttt{H5Pdecode}
  round-trip}): Build a DCPL via \texttt{H5Pappend\_filter\_blob},
  \texttt{H5Pencode} it, and \texttt{H5Pdecode} the result into a new
  DCPL in a separate process with no access to the original file. Verify
  the decoded DCPL's blob bytes are byte-identical to the original,
  confirming \SectionRef{sec:blob-encode-decode}'s inline-serialization
  decision.
\item \texttt{blob-05} (\textbf{\texttt{h5repack} cross-file copy}): Run
  \texttt{h5repack} on a file containing a blob-configured dataset;
  verify the output file's dataset reads back correctly and that its
  blob is stored at a new, independent on-disk locator (not the source
  file's locator), per \SectionRef{sec:blob-repack}.
\item \texttt{blob-06} (\textbf{oversized default-storage blob}):
  Configure a filter via \texttt{H5Pappend\_filter\_blob} with a
  multi-megabyte buffer using the default \texttt{H5HG}-based storage;
  verify create/open succeeds and the runtime chunk I/O path is
  unaffected (compression throughput on the same file is unchanged
  relative to an equivalent dataset without a blob).
\item \texttt{blob-E01} (\textbf{malformed call}):
  \texttt{H5Pappend\_filter\_blob} with \texttt{buf=NULL} and
  \texttt{size>0}, or \texttt{buf!=NULL} and \texttt{size=0}, returns
  \texttt{H5E\_BADVALUE} and does not modify the DCPL.
\item \texttt{blob-E02} (\textbf{unknown filter}):
  \texttt{H5Pappend\_filter\_blob} with an unregistered filter
  \texttt{id} returns \texttt{H5E\_NOFILTER}.
\item \texttt{blob-07} (\textbf{duplicate filter IDs, distinct blobs}):
  Append the same filter ID twice to one pipeline via two
  \texttt{H5Pappend\_filter\_blob} calls with different blobs; verify
  after create/reopen that each pipeline entry recovers its own blob
  (per-entry association, \SectionRef{sec:append-filter-blob}).
\item \texttt{blob-08} (\textbf{per-dataset blobs via copy-then-tweak}):
  Build a base DCPL, \texttt{H5Pcopy} it, append the same filter with a
  different blob in each copy, create two datasets; verify each dataset
  reads back its own blob (\SectionRef{sec:blob-per-dataset}).
\item \texttt{blob-09} (\textbf{path-string dataset association, Use
  Case B pattern; the filter uses its blob on a reopened file}): A test
  filter stores a mask dataset's path in its blob.  Its \texttt{init}
  reads the path with \texttt{H5Pget\_filter\_blob}, opens the mask via
  \texttt{H5Dopen2(file\_id, path, ...)} and keeps it in its state; its
  chunk function checks the mask it is handed on every call; \texttt{term}
  closes it.  Create, write, close the file, reopen, and read.  Verify
  every chunk call on both the write and the read path received the
  correct mask, and that \texttt{term} ran once per open
  (\SectionRef{sec:filter-state}).  The read half
  is the case no pass-through filter test exercises: the data path
  succeeds only if the blob reached the chunk function after a reopen
  (\SectionRef{sec:blob-usecaseb}).
\item \texttt{blob-10} (\textbf{segmented blob}): A 64~MiB blob under
  default storage, in a debug build.  Verify it reads back byte-identical
  after a reopen, and that deleting the dataset frees at least half the
  blob's size (every segment, not just the index).  The debug build is
  the point: the metadata cache asserts on an entry larger than
  \texttt{H5C\_MAX\_ENTRY\_SIZE} (32~MiB) in \texttt{H5C\_insert\_entry},
  and a single-object blob of this size trips that assert --- confirmed by
  running the test with segmentation disabled.
\item \texttt{blob-11} (\textbf{checksum}): Corrupt one byte of a stored
  blob in the file; verify \texttt{H5Dopen} fails with
  \texttt{H5E\_READERROR}.  Repeat for a segmented blob, corrupting a
  byte in a middle segment.
\item \texttt{blob-12} (\textbf{content sharing}): Create three datasets
  from separate DCPLs carrying byte-identical blobs, and one with a blob
  that differs in a single byte.  Verify the file grows by far less than
  the blob's size for the second and third datasets, and by at least its
  size for the fourth.  Delete two of the three and verify almost no space
  is freed and the third still reads its blob; delete the third and verify
  the blob's space is freed; verify the fourth is unaffected, including
  after a reopen.  Run for a single-object and a segmented blob.
\item \texttt{blob-13} (\textbf{custom storage delete}): Register a class
  with custom \texttt{write\_blob}/\texttt{read\_blob}/\texttt{delete\_blob}.
  Deleting the dataset calls \texttt{delete\_blob} exactly once, with the
  locator \texttt{write\_blob} returned (the callback rejects any other).
\item \texttt{blob-14} (\textbf{custom storage without the plugin}):
  Reopen a file with a custom-stored blob after unregistering the filter.
  Verify \texttt{H5Dopen} succeeds without calling \texttt{read\_blob}
  (the test's locator is not a heap address, so reading it as one would
  fail the open), and that \texttt{H5Dread} fails.  Re-registering the
  filter does not help the already-open dataset; reopening it does, and
  the data then reads back correctly.
\item \texttt{blob-E03} (\textbf{partial storage callbacks}):
  \texttt{H5Zregister} rejects a class that sets \texttt{write\_blob} but
  not \texttt{delete\_blob} (or any other strict subset of the three).
\end{itemize}

\subsection{Extension Block Encoding Tests}
\label{sec:test-blob-block}

The blob locator is carried as \texttt{H5O\_PLINE\_EXT\_BLOB}, a critical
extension block in RFC-HDFG-2026-001's version-3 pipeline message
(\SectionRef{sec:blob-format}).  These tests cover the framing rather than
the feature: they are what establishes that a library implementing
version~3 without this RFC behaves safely on a file that uses it.

\begin{itemize}
\item \texttt{blk-01} (\textbf{locator round-trips as a well-formed
  block}): Create a blob-bearing dataset and decode its pipeline message
  directly.  Verify the entry carries exactly one block with
  \texttt{ext\_type = 0x0002}, the critical bit set in
  \texttt{ext\_flags}, \texttt{reserved = 0}, and an \texttt{ext\_length}
  matching the file's address and length sizes.  Verify the decoded
  locator recovers the same blob bytes.
\item \texttt{blk-02} (\textbf{coexistence with a configuration string}):
  Append a filter with both a parameter string and a blob; verify the
  entry carries \texttt{H5O\_PLINE\_EXT\_CONFIG} and
  \texttt{H5O\_PLINE\_EXT\_BLOB} in ascending \texttt{ext\_type} order,
  and that both round-trip independently.
\item \texttt{blk-03} (\textbf{a version-3-only library rejects safely}):
  The central compatibility claim of this RFC.  Build the library with
  \texttt{H5O\_PLINE\_EXT\_BLOB} support compiled out --- version~3
  otherwise intact --- and open a file written with it.  Verify: a
  blob-bearing dataset fails to open with an error naming the
  unrecognised block type and the filter ID; a sibling dataset in the
  same file with only a configuration string opens normally and returns
  its string; and no blob-bearing dataset is ever filtered using
  \texttt{cd\_values} alone.  The last assertion is the one that matters
  --- silently proceeding is the failure mode the critical bit exists to
  prevent.
\item \texttt{blk-04} (\textbf{libver bound is a hard error}): Set an
  \texttt{H5Pset\_libver\_bounds} upper bound of
  \texttt{H5F\_LIBVER\_V200}, configure a blob-bearing filter with no
  configuration string, and verify \texttt{H5Dcreate} fails with
  \texttt{H5E\_BADRANGE} rather than writing a message with the locator
  dropped (\SectionRef{sec:blob-format}); verify \texttt{H5Ocopy} of a
  blob-bearing dataset into a file with that bound fails the same way.
  The behaviour is identical to that of a configuration-string-only
  pipeline under the same bound (RFC-HDFG-2026-001 \texttt{fmt-05}).
\item \texttt{blk-05} (\textbf{no version~4}): Verify that a file written
  with a blob carries pipeline message version~3, not~4 --- i.e.\ that
  this RFC introduced no message version of its own.
\end{itemize}

\subsection{Parallel HDF5 Tests}
\label{sec:test-parallel}

These tests require a Parallel HDF5 build and at least two MPI ranks.
They validate the proposed collective identical-insert protocol
(\SectionRef{sec:blob-parallel}) and are prerequisites for marking that
protocol resolved.

\begin{itemize}
\item \texttt{par-blob-01} (\textbf{collective identical insert}): All
  ranks call \texttt{H5Pappend\_filter\_blob} with identical arguments,
  followed by a collective \texttt{H5Dcreate}. Verify that every rank
  independently computes the identical \texttt{H5Z\_blob\_loc\_t}
  (compare via \texttt{MPI\_Allgather}), that the file contains exactly
  one heap object for the blob, and that the file passes
  \texttt{h5debug}/\texttt{h5stat} integrity checks after close.
\item \texttt{par-blob-02} (\textbf{cache-state consistency}): After the
  collective create, force metadata-cache sync points (many further
  metadata operations) and close collectively; verify no hang and no
  corruption --- this exercises the \texttt{dirty\_bytes}/sync-point
  accounting that the rank-0-only design would have broken.
\item \texttt{par-blob-03} (\textbf{read path}): Reopen the file with all
  ranks and independently read the filtered dataset; verify blob
  recovery on every rank.
\item \texttt{par-blob-04} (\textbf{allocation-settings matrix}): Repeat
  \texttt{par-blob-01} under paged allocation and non-default
  free-space-manager settings (\SectionRef{sec:blob-parallel} open
  items).
\item \texttt{par-blob-05} (\textbf{segmentation and sharing in
  parallel}): Repeat \texttt{par-blob-01} with a blob larger than one
  segment, then create a second dataset whose DCPL is built separately
  on each rank but carries identical blob bytes.  Verify every rank
  computes identical locators, that the second dataset shares the first
  one's object, and that the file passes \texttt{h5debug}/\texttt{h5stat}
  checks (\SectionRef{sec:blob-sharing}).
\item \texttt{par-state-01} (\textbf{per-dataset state on every rank}):
  With a filter defining \texttt{init}/\texttt{term}, registered before
  the collective calls, create, write collectively, close, reopen, and
  read on all ranks; verify \texttt{init} and \texttt{term} each ran once
  per rank per open, and that every rank's chunks received that rank's
  state (\SectionRef{sec:filter-state-parallel}).
\end{itemize}
